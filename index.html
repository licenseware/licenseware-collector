Software inventory agent

What is LICENSEWARE Collector?

A free lightweight agent that collects system and software inventory data from your servers and securely transmits it to the LICENSEWARE™ platform for software license compliance analysis.

Download Installation guide Current release 0.17.0

Operating System Compatibility

Linux

  • x86_64 and arm64 (64-bit)
  • systemd required
  • RHEL, Ubuntu, Debian, etc.

Windows

  • x86_64 (64-bit) only
  • Windows 10+ (Desktop)
  • Windows Server 2016+

macOS

  • Intel & Apple Silicon
  • macOS 12+
  • launchd service
⚠️ Older Windows versions
Windows 7, Windows 8.1, Windows Server 2012 R2 and earlier are not supported. The agent requires Windows 10 or Windows Server 2016 or later.

Network Requirements

  • api.licenseware.io or api.us.licenseware.io or api.au.licenseware.ioHTTPS 443
    Data ingestion, enrolment and configuration. Allow the one for your region: api.licenseware.io (EU), api.us.licenseware.io (US) or api.au.licenseware.io (AU). The agent uses the one named in your enrolment token.
  • pushlogs.licenseware.io or pushlogs.us.licenseware.io or pushlogs.au.licenseware.ioHTTPS 443
    Agent log shipping, on by default (LOG_SHIP_ENABLED). Allow the one for the same region: pushlogs.licenseware.io (EU), pushlogs.us.licenseware.io (US) or pushlogs.au.licenseware.io (AU).
  • cdn.licenseware-collector.comHTTPS 443
    Installer downloads, agent updates (signed manifest and packages) and osquery updates, which the agent checks continuously. Required continuously, not just at install time.
⚠️ Firewall Configuration
Ensure outbound HTTPS (port 443) is allowed to the domains listed above. No inbound ports required.

Upgrading to 0.17.0

From 0.17.0 every agent updates itself from cdn.licenseware-collector.com: signed updates, a staged rollout, and an automatic rollback if a new version fails to start. How a device gets to 0.17.0 depends on its OS.

Windows: upgrade with the 0.17.0 MSI

Windows agents on 0.16.x do not update themselves to 0.17.0; they keep running until you upgrade them. In Intune, SCCM or your other tool, replace the 0.16.x package with the 0.17.0 MSI and deploy it as an in-place upgrade with the same command line. An enrolled device needs no token. Do not configure an uninstall followed by an install. If a service is stopped afterwards, run Restart-Service licenseware-collector.

macOS: update privacy rules, then deploy the 0.17.0 pkg

Macs on 0.16.x do not update themselves. From 0.17.0 the collector's code-signing identifier is io.licenseware.collector (osquery: io.licenseware.collector.osqueryi); earlier builds used licenseware-collector, LicensewareCollector and osqueryi. If your MDM has PPPC or other privacy rules that name the collector by identifier, add the new identifiers first and keep the old ones until every Mac is upgraded. Rules that use the Team ID 8MD7XA4CF3 need no change. Then deploy LicensewareCollector.pkg 0.17.0 through your MDM; an enrolled Mac needs no token.

Linux: nothing to do

Linux agents on 0.16.x update themselves to 0.17.0 within a day. Nothing to do.

Agents on 0.11.0 or older

These never update to 0.17.0. Reinstall them with the current package from Downloads.

After 0.17.0

Every OS updates itself from the CDN. To keep one device on its current version, turn its updates off with AUTOUPDATE=0 (see Settings).

Installation Guide

1

Get Your Token

  1. Go to LICENSEWARE and sign in or create a free account
  2. Navigate to LC App and go to API Keys tab
  3. Click Create Key, configure it, and copy the token
2

Download and Install

Linux (.deb / .rpm)

⚠️ Requires root privileges

  1. Install and enrol in one step 
    curl -fsSL https://cdn.licenseware-collector.com/install.sh | sudo TOKEN=<enrolment-token> sh

    The script picks the right package, checks its SHA256SUMS, installs it, waits for registration and removes what it installed if the machine does not register. Extra options: --proxy URL, --version V, --dry-run. If your sudo rules refuse TOKEN=, save the token in a file and use ... | sudo sh -s -- --token-file /root/lc-token.

  2. Or download the package and install it yourself 
    curl -fsSLO https://cdn.licenseware-collector.com/d/latest/licenseware-collector_amd64.deb
    sudo TOKEN=<enrolment-token> apt install ./licenseware-collector_amd64.deb

    On RHEL / Fedora / SUSE use sudo TOKEN=<enrolment-token> dnf install ./licenseware-collector_amd64.rpm. Put TOKEN= after sudo, not before it (TOKEN=... sudo apt loses the variable). The package waits up to a minute and says whether registration finished.

    If sudo refuses TOKEN=, use sudo env TOKEN=<enrolment-token> apt install ..., or create /etc/default/licenseware-collector (mode 0600) containing TOKEN=<enrolment-token> and install without the variable. A fresh install without a token is refused before anything is written.

  3. Check it works 
    licenseware-collector status

    Exit code 0 and registered in the output mean the machine is enrolled.

Full Command Reference

The command is on your PATH on Linux and macOS (run it with sudo where it changes something). Proxy, custom CA certificate and the other settings are described in Settings; change them at any time with sudo licenseware-collector set.

Flag / Variable Required Description
TOKEN Yes Enrolment token from the LICENSEWARE platform, given at install time. LICENSEWARE_ENROLL_TOKEN is deprecated and prints a warning; LICENSEWARE_TOKEN, ENROLL_TOKEN and --enroll-token are no longer accepted.
PROXY, NO_PROXY, CA_CERT No Optional settings for a proxy and a custom CA certificate. See Settings.

macOS (.pkg)

⚠️ Requires root privileges

  1. Install and enrol in one step 
    curl -fsSL https://cdn.licenseware-collector.com/install.sh | sudo TOKEN=<enrolment-token> sh

    Downloads the package, checks its SHA256SUMS, installs it and waits for registration (up to 3 minutes).

  2. Or install by hand 
    curl -fsSLO https://cdn.licenseware-collector.com/d/latest/LicensewareCollector.pkg
    sudo install -m 0600 /dev/null /usr/local/etc/licenseware-collector
echo 'TOKEN=<enrolment-token>' | sudo tee /usr/local/etc/licenseware-collector >/dev/null
sudo installer -pkg LicensewareCollector.pkg -target /

    installer does not pass environment variables to the package, so the token goes in the env file first. If it fails, the reason is in /var/log/install.log.

  3. Check it works 
    licenseware-collector status

    Exit code 0 and registered in the output mean the Mac is enrolled.

Deploying with an MDM? See MDM Deployment. To upgrade an enrolled Mac, run the installer step again; no token is needed.

Windows

⚠️ Requires Administrator privileges

  1. Download the installer 
    Invoke-WebRequest -Uri https://cdn.licenseware-collector.com/d/latest/LicensewareCollector.msi `
  -OutFile LicensewareCollector.msi
  2. Install, passing the enrolment token 
    msiexec /i LicensewareCollector.msi /qn TOKEN=<enrolment-token>
    The token is marked as a secure property, so it is never written to the MSI log. To keep it off the command line, put it on the first line of a file and pass TOKENFILE=C:\path\token.txt instead. Run the same command with a newer .msi to upgrade in place; an enrolled machine needs no token. Exit code 0 means the machine is registered and the service is running (the installer waits up to 3 minutes). On failure it exits with 1603, rolls back completely and leaves %ProgramData%\Licenseware\setup.log with the reason. Installing without a token is refused.
  3. Check it works 
    LicensewareCollector status
    In a new elevated prompt (so the updated PATH is loaded). Exit code 0 and registered in the output mean the machine is enrolled.

Unattended / MDM deployment (Intune, SCCM)

The install runs as SYSTEM and is fully unattended: msiexec /i LicensewareCollector.msi TOKEN=<enrolment-token> /qn /norestart. The installer waits until the agent is registered and its service is running (up to 3 minutes). If that does not happen it exits 1603 and rolls everything back.

Deployment of the Collector through automated tools such as Intune or SCCM constitutes acceptance of the Collector Licence Agreement by the deploying organisation.

Exit codes

Code Meaning
0 Installed. On a fresh install this means the agent is registered and the service is running
3010 Success, reboot pending (files in use; the package itself schedules no reboot)
1603 Refused or failed, and rolled back completely. On a fresh install this covers a missing token, a token the backend rejected, and an agent that was not registered within 3 minutes. The reason is in %ProgramData%\Licenseware\setup.log
1618 Another installation is already in progress
1619 / 1620 Package path unreachable, or not a valid installer package

These are standard Windows Installer codes. There are no vendor-specific values.

Upgrades

Run the new MSI in place with the same command line. In Intune or SCCM, replace the old package with the new one; do not configure an uninstall followed by an install. An enrolled host needs no token, and a stopped service is started.

Detecting a registered agent

The agent records whether the LICENSEWARE backend has acknowledged it. On Windows that state is mirrored into the registry, so Intune and SCCM can use a built-in registry rule — no script. Do not use a file-version or product-code rule: both report success even when the agent is not registered.

Setting Value
Rule type Registry
Key path HKEY_LOCAL_MACHINE\SOFTWARE\Licenseware\Collector
Value name Registered
Detection method Integer comparison, Equals, 1
Associated with a 32-bit app on 64-bit clients No

SCCM uses the same key and value for an application detection method and for a compliance configuration item. The key also carries Status, AgentId, DeviceUuid, Version, RegisteredAt and LastContactAt as strings for hardware inventory.

On every platform the same information is in a world-readable file with no secrets: registration.json in the agent's state directory (see Installation Paths). Its status is enrolled until the backend acknowledges the agent, then registered. The status command reads it and exits 0 only when registered (2 enrolled only, 3 no state file, 4 no service); status --json prints the file. 

licenseware-collector status --json
jq -e '.status == "registered"' /var/lib/licenseware-collector/registration.json
⚠️ Never use --require-healthy in a detection rule
Use the registry value or status exit code 0. status --require-healthy exits 5 whenever the agent is not working at that moment (offline, service stopped), so a required assignment would reinstall the agent on those devices.

Full Command Reference

To enrol or repair a machine by hand, run this in an elevated prompt: 

$env:TOKEN = "<enrolment-token>"
LicensewareCollector register

TOKEN is the only token input. The ENROLLTOKEN MSI property is a deprecated alias, and the LICENSEWARE_ENROLL_TOKEN variable is deprecated (read with a warning). ENROLL_TOKEN is no longer read.

Proxy, custom CA, auto-update and log level (PROXY, NO_PROXY, CA_CERT, AUTOUPDATE, LOG_LEVEL) are settings, not flags: see Settings.

macOS (Jamf, Intune, Kandji)

The pkg enrols itself, but installer does not pass it environment variables, so the token reaches the Mac in a configuration profile. Three steps:

  1. Upload the profile io.licenseware.collector.mobileconfig with device scope. Replace REPLACE_WITH_ENROLMENT_TOKEN with your token, and set PROXY, NO_PROXY or CA_CERT if you need them.
  2. Deploy LicensewareCollector.pkg. The order does not matter: a pkg that runs before the profile fails with exit 20 and the MDM retries it.
  3. Add status-attribute.sh as an extension attribute (Jamf; use --plain for Intune or Kandji custom attributes). It reports registered once the Mac is enrolled. Build a smart group of Macs whose value is not registered and scope the profile to it, so the token leaves each Mac once it is registered.

The pkg waits up to 3 minutes for registration. Exit codes: 20 no token, 21 token rejected, 22 enrolment failed, 23 timed out. The reason is in /var/log/install.log.

The signing identifier is io.licenseware.collector (and io.licenseware.collector.osqueryi), for identifier-based PPPC rules. Rules based on the Team ID are unaffected.

Settings

Settings are stored on the machine and win over the LICENSEWARE control plane. Change them with the set command, at install time, or through your MDM profile.

Setting What it does Default
PROXY Proxy URL for all collector traffic, or direct to never use a proxy. Detected system proxy, else none
NO_PROXY Comma-separated hosts, .domains or CIDRs that bypass the proxy. None
CA_CERT Path of a PEM file with extra CA certificates (TLS-inspecting proxy). None
LOG_LEVEL debug, info, warn, error or critical. info
AUTOUPDATE 0 turns the collector's self-update off on this machine. On
LOG_SHIP_ENABLED false stops sending the collector's own log to LICENSEWARE. true

Where to set them

  • Windows MSI: properties PROXY, NO_PROXY, CA_CERT, AUTOUPDATE and LOG_LEVEL on the msiexec command line.
  • macOS profile: keys TOKEN, PROXY, NO_PROXY, CA_CERT, AUTOUPDATE and LOG_LEVEL in io.licenseware.collector.mobileconfig.
  • Any time, any OS: the set command below. It checks the value, stores it and restarts the service.
Linux / macOS 
sudo licenseware-collector set
sudo licenseware-collector set LOG_LEVEL=debug
sudo licenseware-collector set PROXY=

The first command lists every setting with its value and source. A trailing = with no value removes the setting.

Windows (elevated prompt) 
LicensewareCollector set LOG_LEVEL=debug

Older names are still read: CA_CERT_PATH, SELF_UPDATE_ENABLED, HTTPS_PROXY / HTTP_PROXY and no_proxy. On/off values accept 1/0, true/false, yes/no and on/off.

Settings live in an environment file: Linux /etc/default/licenseware-collector, macOS /usr/local/etc/licenseware-collector, Windows %ProgramData%\Licenseware\collector.env. Prefer set over editing it. The service reads the file only at start, so after a hand edit run sudo licenseware-collector restart (Windows: LicensewareCollector restart).

Proxy Configuration

If your network requires an HTTP proxy for outbound connections, the collector sends all its traffic through it.

System proxy detection

On Windows (the machine WinHTTP proxy, or the Internet Explorer proxy when it is set per machine by policy) and on macOS (System Settings > Network > Proxies) the collector finds the proxy by itself. It does not detect PAC/WPAD scripts, per-user proxies, or any proxy on Linux: set PROXY there. PROXY=direct forces a direct connection.

Basic authentication goes in the URL: http://user:password@proxy.corp.com:8080. NTLM and Kerberos proxies are not supported.

Set it at install

  • install.sh: add --proxy http://proxy.corp.com:8080 (... | sudo TOKEN=<enrolment-token> sh -s -- --proxy URL).
  • Windows MSI: add PROXY=http://proxy.corp.com:8080 to the msiexec command.
  • macOS: set the PROXY key (and NO_PROXY if needed) in the configuration profile.
  • Linux package: before installing, create /etc/default/licenseware-collector (mode 0600) with a PROXY= line.

Change it afterwards

Use set. It checks the value, stores it and restarts the service.

Linux / macOS 
sudo licenseware-collector set PROXY=http://proxy.corp.com:8080
sudo licenseware-collector set NO_PROXY=localhost,127.0.0.1,.internal.corp
Windows (elevated prompt) 
LicensewareCollector set PROXY=http://proxy.corp.com:8080

Custom CA Certificates

Corporate proxies that perform TLS inspection inject their own CA certificate into the chain. The collector must trust it, otherwise all HTTPS connections fail. Point CA_CERT at a PEM file with your CA certificate(s); it works on every OS.

Custom certificates are added to the system certificate pool, not replacing it. All standard system CAs remain trusted.

Set it at install

  • Windows MSI: add CA_CERT=C:\path\corp-ca.pem to the msiexec command. The file is copied to %ProgramData%\Licenseware\ca.pem, so the original can go.
  • macOS: set the CA_CERT key in the configuration profile, pointing to a PEM file on the Mac.
  • Linux package: before installing, create /etc/default/licenseware-collector (mode 0600) with CA_CERT=/etc/ssl/certs/corp-ca.pem.

Change it afterwards

Linux / macOS 
sudo licenseware-collector set CA_CERT=/etc/ssl/certs/corp-ca.pem
Windows (elevated prompt) 
LicensewareCollector set CA_CERT=C:\ProgramData\Licenseware\ca.pem

Uninstall Guide

⚠️ Requires elevated privileges (sudo on Linux/macOS, Administrator on Windows)

Linux

  1. Debian / Ubuntu
    sudo apt remove licenseware-collector
  2. RHEL / Fedora / SUSE
    sudo dnf remove licenseware-collector

Removing the package stops the service and removes the collector. sudo licenseware-collector uninstall --force does the same: it removes the package through apt or dnf for you.

macOS

Run this in Terminal, or download uninstall.command from the Downloads section and double-click it: 

sudo licenseware-collector uninstall --force

Windows (Administrator PowerShell)

  1. Run the uninstall command (it runs msiexec /x for you)
    LicensewareCollector uninstall --force
  2. Or uninstall the package directly 
    msiexec /x LicensewareCollector.msi
  3. Or remove it from the UI:
    Settings > Apps > Installed apps
Uninstalling stops the service, removes it, and deletes the collector's runtime files and enrolment token from the machine. Without --force, uninstall refuses while the service is running (stop it first with stop). Add --remove-osquery to remove osquery too.

Data Collection Specification

This section lists every query the Collector runs, the operating systems it runs on, how often, the exact fields collected and why. It is the same specification published as Schedule 3 of the Licenseware Data Processing Addendum, which governs all data transmitted by the Collector. Nothing outside this list is collected.

The Collector runs two fixed catalogues. Catalogue definitions are fetched from the platform every 30 minutes and results are sent over TLS to the regional instance encoded in your enrolment token. Field names are the column names of the underlying osquery tables.

The query, field and purpose tables below are published in English. The English text is the operative version regardless of the language selected for this site.

What the Collector does not collect

  • File contents, documents, email or messaging content
  • Browser history, keystrokes, screen content or network traffic
  • Process command-line arguments or program argument strings (removed from all queries on 3 September 2026)
  • Anything outside the queries listed below. Where a query is restricted to named directories or registry keys, the restriction is shown in the field list.

Personal data

Several queries return personal data about the people who use the system: local usernames and home paths, logged-in sessions, per-user program execution history and process ownership. These are flagged in the right-hand column. If you deploy the Collector you are the controller of that data and should cover it in employee privacy notices and, where required, works council consultation before rollout. Our DPIA Support Document (Processor Information) walks through each item.

Operational logs

The agent ships its own operational logs (status, errors, ingestion cycle information) to pushlogs.licenseware.io or the regional equivalent by default. They may incidentally contain hostnames or file paths. Set LOG_SHIP_ENABLED=false in the environment file and restart the service to disable log shipping. Logs are processed under the DPA.

  • sudo licenseware-collector updateCheck for and apply an agent update (-c checks only)
  • sudo licenseware-collector uninstall --forceRemove the collector
  • sudo licenseware-collector run-onceRun every query once (for testing)
  • licenseware-collector system-infoPrint this machine's identifiers as JSON
  • licenseware-collector licencePrint the licence agreement and third-party notices

On Linux and macOS use licenseware-collector; on Windows use LicensewareCollector from an elevated prompt. It is on the PATH: /usr/bin/licenseware-collector on Linux, a link at /usr/local/bin/licenseware-collector on macOS, and %ProgramData%\Licenseware\bin in the machine Path on Windows (open a new elevated prompt after installing).

Logs & Troubleshooting

First steps

Run status first. It says whether the service is running and when the last collection and upload happened. If something is wrong, run diagnose and send us the zip it writes in the current directory. It is redacted: it holds no tokens and no query output.

Linux and macOS: 
licenseware-collector status
licenseware-collector diagnose
Windows (elevated prompt): 
LicensewareCollector status
LicensewareCollector diagnose

Below is where to read the collector's logs. It writes them to standard error; the Windows service writes them to the Windows Event Log instead. How you access them depends on the operating system and service manager.

Log Level

The verbosity is controlled by the LOG_LEVEL setting. The default is info. Change it with sudo licenseware-collector set LOG_LEVEL=debug; this restarts the service.

Level Description
debug Most verbose — all messages including internal state
info Operational messages (startup, ingestion cycles) (default)
warn Non-critical issues that may need attention
error Failures only
critical Fatal errors that stop the service

Linux

On systemd-based systems, logs are captured by the journal automatically.

Follow logs in real time:
journalctl -u licenseware-collector -f
View logs from the last hour:
journalctl -u licenseware-collector --since "1 hour ago"

macOS

The launchd service writes both stdout and stderr to a single log file.

Follow logs in real time:
tail -f /var/log/licenseware-collector.log
View full log file:
cat /var/log/licenseware-collector.log

Windows

The Windows service writes the collector's own log to the Windows Event Log under the licenseware-collector provider; it writes no log file. Run these in an elevated PowerShell.

1. Read the collector's log (the last 50 events):
Get-WinEvent -ProviderName "licenseware-collector" -MaxEvents 50
2. Pull Service Control Manager events (start, stop, crash, recovery) for the last 24 hours: 
Get-WinEvent -FilterHashtable @{
  LogName   = 'System'
  StartTime = (Get-Date).AddDays(-1)
  ProviderName = 'Service Control Manager'
} | Where-Object { $_.Message -match 'licenseware-collector' } |
  Format-List TimeCreated, Id, LevelDisplayName, Message
3. Capture the full application output by stopping the service and running one collection cycle interactively. All logs stream to the console: 
Stop-Service licenseware-collector
$env:LOG_LEVEL = 'debug'
LicensewareCollector run-once *>&1 |
  Tee-Object -FilePath "$env:USERPROFILE\licenseware-collector-debug.log"
Start-Service licenseware-collector
The *>&1 redirection merges every PowerShell stream (stdout, stderr, warnings, verbose, debug) so nothing the collector writes is lost.
4. If the installer finishes but no service appears, read the installer's own log. It records why enrolment failed and survives the rollback that removes everything else. The enrolment token is never written to it: 
Get-Content C:\ProgramData\Licenseware\setup.log
Debugging Tip
Run sudo licenseware-collector set LOG_LEVEL=debug to get the most verbose output (it restarts the service). When you are done, run sudo licenseware-collector set LOG_LEVEL= to go back to the default.
